## 5. Request weather data

```python
def get_weather(self):
    api_key = "..."
    city = self.city_input.text()
    url = f"https://api.openweathermap.org/data/2.5/weather?q={city}&appid={api_key}"
```

- `api_key` identifies your app to OpenWeatherMap.
- `.text()` reads what the user typed.
- The `f"..."` is an *f-string*: Python inserts the values of `{city}` and `{api_key}` into the URL.

The URL asks the service for the current weather for that city. A safer version handles spaces and special characters in city names:

```python
response = requests.get(
    "https://api.openweathermap.org/data/2.5/weather",
    params={"q": city, "appid": api_key},
    timeout=10,
)
```

`params` lets `requests` encode the query values properly. `timeout=10` prevents the app from waiting indefinitely if the server doesn’t respond.

## 6. Handle the response and errors

```python
try:
    response = requests.get(url)
    response.raise_for_status()
    data = response.json()
    print(data)
```

`try` marks code that could fail.

- `requests.get(url)` sends a GET request to the API.
- `raise_for_status()` raises an HTTP error for an unsuccessful status code, such as 404.
- `.json()` converts the response body from JSON text into Python data, usually dictionaries and lists.
- `print(data)` prints that data in the terminal, which is useful while learning and debugging.

```python
if data["cod"] == 200:
    self.display_weather(data)
```

The API uses code `200` to indicate success. If the response is successful, the program passes the returned data to `display_weather`.

The API key in your pasted code may have been exposed. Revoke or regenerate it, then load the new key from an environment variable instead of writing it directly into the program.

Your exception handlers show an error message in the window:

```python
except requests.exceptions.HTTPError as http_err:
```

This handles an HTTP error raised by `raise_for_status()`. The `match response.status_code` block checks the status code and picks a message:

- `400`: the request was invalid.
- `401`: the API key may be missing or incorrect.
- `404`: the city wasn’t found.
- `500`, `502`, `503`, `504`: server or gateway problems.
- `case _`: any other HTTP status.

Other handlers cover connection failures, timeouts, redirects, and general request problems. The API may also return an error response with a `200` HTTP status, so later you may want to check the response’s `cod` and `message` fields explicitly.

At the moment, the program calculates both but displays only Fahrenheit:


The `:.0f` formats the number with zero digits after the decimal point. Some emoji and degree characters in the pasted file appear garbled, likely because of text encoding. In your Python file, use `"°F"` for the degree symbol and paste the emoji again as Unicode text if needed.

```python

```

The API’s `weather` value is a list. `[0]` selects its first item. These lines read that item’s condition code and description.


These put the matching emoji and description into their labels.

`@staticmethod` means this helper method doesn’t need to read or change the app window (`self`). It takes a weather condition ID and returns an emoji.

## How the whole app flows

1. Python imports the libraries and defines the `UcheWeatherApp` class.
2. The final `if` block creates and displays the window.
3. The user enters a city and clicks the button.
4. The button connection calls `get_weather()`.
5. `get_weather()` requests data from the API and handles errors.
6. On success, `display_weather()` fills in the temperature, emoji, and description.
